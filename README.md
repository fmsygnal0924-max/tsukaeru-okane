# Yohaku（余白）

口座残高と楽天カードの数字から「本当に使えるお金」を出す、iPhone 用の家計アプリ（PWA）。
このフォルダの中身をそのまま GitHub Pages に置き、Safari の「ホーム画面に追加」で全画面アプリとして使う。

- index.html … アプリ本体。データは端末内（localStorage）のみで、金額はこのファイルに含まれない
- manifest.webmanifest … 全画面起動の設定
- sw.js … キャッシュ優先で即起動・オフライン対応
- icons/ … アプリアイコン
- splash/ … iPhone の起動画面

## 利用月と支払い月

- 生活費、週のペース、カード利用目標は利用日で集計。支払い月を修正しても利用日は変えない。
- 通常カードは月末締め・翌月払いの**見込み**。楽天カードから楽天キャッシュへのチャージは25日締めで、26日以降は翌々月払いの見込み。キャッシュでの支払い自体や銀行からのチャージには適用しない。
- `method=charge` は既存の「カードから楽天キャッシュへチャージ」専用区分。`method=card` で取り込まれたチャージは、明示的なチャージ名称の完全一致で判定する。メモに単に「楽天キャッシュ」が出てくるだけでは判定しない。
- 公式の締め日: https://support.rakuten-card.jp/faq/show/9?site_domain=guest
- 店名やメールの受信日から実際の請求月を断定しない。楽天の個別明細で確認した月を「履歴 → 請求月別の記録 → 請求月」で指定すると優先する。
- 請求月の補足・月別の確定額は既存の state.overrides.billing に保持。log の利用日、金額、IDは移動・削除しない。confirmed 0円も有効。
- 口座全体の参考額は、今月支払い分＋将来支払い分をそれぞれ一度だけ引く。生活費の利用額をさらに二重に引かない。
- 「今月支払い額」は今の暦月の支払い分。照合額は支払い月／利用月と対象月を選ぶ。合計一致だけでは明細の一致や請求確定を意味しない。
- 過去の数値履歴・照合記録は書き換えない。現在の見込みは最新記録から再計算される。未記録のサブスク予測は設定に基づく概算で、実際の請求額は楽天明細で確認する。
- Apps Script側の週次レポート生成コードはこのリポジトリに含まれない。この変更のみでサーバー側レポートの計算式が変わるわけではない。

## 検証

```sh
node --test tests/billing.test.cjs
npm install --ignore-scripts
npm run test:dom
```

`test:dom` はローカルの合成データでアプリ全体を読み、締め日境界、年越し、請求月変更、確定0円、引落済み、同期・旧データ互換性を検証する。実際の同期先にはアクセスしない。
任意で `YOHAKU_PRIVATE_FIXTURE` に非公開のローカル検証データのパスを指定できる。実データや金額、識別子をこの公開リポジトリに保存しない。
`tests/app.test.cjs` は Playwright と Chromium のある環境で同じ流れをブラウザー検証するための任意テスト。
